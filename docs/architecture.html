System Reference

Factory Inventory Management System

A demo full-stack inventory and operations dashboard. A Vue 3 single-page app talks over HTTP/JSON to a Python FastAPI service, which serves seven JSON fixture files held entirely in memory. There is no database and no persistence layer — restarting the API resets all state.

Vue 3 SPA · port 3000 FastAPI · port 8001 In-memory JSON fixtures Read-mostly · no auth

03 — Data flow

How a filter change reaches the screen

The four global filters — Time Period, Location, Category, Order Status — are the spine of the app. They live in one shared composable and are re-sent to the API on every change; filtering is server-side, presentation maths is client-side.

  1. User changes a filter in FilterBar.vue
    The bar is mounted once in App.vue, above <router-view>, so it persists across route changes.
  2. State lands in useFilters.js
    Four refs declared at module scope, outside the exported function — every importer shares one instance, giving a store without a store library.
  3. Views read it via getCurrentFilters()
    Returns a plain object; the period value is remapped onto the API's month parameter.
  4. api.js builds the query string
    Each method drops any filter equal to 'all' via URLSearchParams, so a default request carries no params at all.
  5. FastAPI receives optional query params
    Every filter is Optional[str] = None, so endpoints stay callable with no arguments.
  6. Server filters the in-memory lists
    apply_filters() chains warehouse / category / status, rebinding a new list each time rather than mutating the global. filter_by_month() handles both 2025-09 and Q3-2025 via QUARTER_MAP.
  7. Pydantic validates the response
    response_model=List[…] coerces and strips fields on the way out — a JSON shape change that outruns the model surfaces here as a 500.
  8. Raw JSON is stored in refs
    Views keep the untouched payload in allOrders, inventoryItems, etc. Nothing is transformed on assignment.
  9. Computed properties derive everything shown
    KPIs, chart series, status splits and currency formatting are all computed() off the raw refs, so a locale switch re-renders without a refetch.

06 — Worth knowing

Observations from the code

Things that are not obvious from the file tree and would otherwise cost you an afternoon.

Four client API methods have no server route
Everything under /api/tasks and /api/purchase-orders is defined in client/src/api.js and wired into the Tasks modal and purchase-order flow, but no matching handler exists in server/main.py. Those calls 404 at runtime.
views/Backlog.vue is orphaned
It has no route in main.js and is imported nowhere. The backlog table users actually see is rendered inside Dashboard.vue, alongside BacklogDetailModal.
purchase_orders.json is an empty array
So has_purchase_order on every backlog item currently evaluates to false, and there is no way to make it true without a working create route.
The API origin is hard-coded
API_BASE_URL in api.js is the literal string http://localhost:8001/api. There is no environment variable and no Vite proxy, so the app only works against a local backend as written.
Month filtering keys off order_date only
filter_by_month() does a substring match against item.get('order_date', ''). Any record type without that field silently passes through unfiltered rather than being excluded.
Nothing you do in the UI survives a restart
All data is module-level Python lists populated once at import. There is no write-back to server/data/, no database, and no cache invalidation to reason about.
